Study this project

For someone who wants to learn from this project rather than follow it: what to read in which order, the ideas you need, the words we use, how to run it yourself, and a few exercises.

Reading order

  • Overview (5 min): the idea and the goal.
  • The data (5 min): what one label is.
  • The model (5 min).
  • Training and Log: dev scores per round.
  • Code: c/bv.c (bv_grade, rollout, canon), bv/student.py, train.py, match.py.

    Key concepts

    Paired rollouts (common random numbers): every candidate buy sees the same shuffles, so the difference between two candidates has far less noise than either value. In bv_grade. People forget it only helps the difference, not the absolute value.
    Winner's curse: pick the best of six noisy estimates and it is too optimistic. The first gate lost (41.5%) for this reason. Fix: require a gain of 2 standard errors, or learn from many positions.
    Policy improvement: with continuation c2, the rollout values are c2's Q-values. Acting greedily on true Q-values is never worse than c2, but only on true ones, not noisy ones.
    Distillation / Expert Iteration: a slow teacher labels positions, and a fast student learns to imitate the teacher's values. DAgger then collects labels from the positions the student itself reaches.
    Deep Sets: one shared network per card plus symmetric pooling. The order of cards doesn't matter, and knowledge transfers between similar cards.
    Information sets: the teacher may only use what the player sees. Hidden zones are canonicalised and resampled, so two positions that look the same give the same labels.

    Reproduce it

    git clone --recursive https://github.com/JCA374/dominion-bv-v1 && cd dominion-bv-v1
python -m venv .venv && .venv/bin/pip install numpy torch pytest
.venv/bin/python -m pytest -q tests        # ~10 s: student C/torch parity, teacher reproducibility
.venv/bin/python match.py --name gate --bv 1 --k0 32 --k1 32 --margin 0.02 --z 2 --kingdoms 40   # teacher vs c2
.venv/bin/python -u train.py --run p1      # the curriculum (hours per round on 8 cores)
    Frozen models c1 2300 and c2 2654 are in models/.

    Exercises

    1. Change --z in the gate (0, 1, 2, 3). Expect a lower override rate and a score closer to 50% as z rises. Where is the best?
    2. Raise topn from 5 to 10 in train.py CFG. Does dev regret fall, and what does each label cost?
    3. Train a flat MLP on the same labels (replace Student) and compare dev regret: does the set structure help?
    4. Measure label noise: grade the same positions twice with different seeds and compute the agreement on the best candidate.
